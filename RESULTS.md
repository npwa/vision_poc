# PPE Model Test Suite Results

Generated by `test_ppe_models.py`, which runs every frame of both test
videos through all 4 models named in the README's model table — the 2
Grounding DINO detector variants crossed with the 2 SAM segmenter variants
(`sam-vit-large` stands in for the README's "large / huge" row; huge is
even bigger/slower and only estimated below, not run) — using the same
detection + geometric compliance logic as `ppe_zero_shot_pipeline.py`
(prompt `"person. hard hat."`, `head_has_hat()` overlap check).

**Design note:** the compliance answer and its confidence score come
entirely from the Grounding DINO detector. SAM only produces segmentation
masks for the overlay video and has no independent way to answer a yes/no
compliance question, so swapping SAM variants never changes the answer or
confidence for a given detector — it only changes VRAM/speed. Both SAM
variants were still run on every frame here (mirroring real pipeline use)
so their resource cost could be measured for the hardware table below.

Per-video verdict = majority vote across all frames with a detected person
(weighted toward whichever side — compliant/non-compliant — had more
agreeing frames); confidence = mean detection score of the agreeing frames.

## 1. Compliance answers per model, per video

| Model combo | 20260824_174509.mp4 | 20260824_174640.mp4 |
|---|---|---|
| grounding-dino-tiny + sam-vit-base  | **Person WITHOUT hard hat** (conf 0.83, 176/215 frames agree) | **Person WITH hard hat** (conf 0.88, 108/128 frames agree) |
| grounding-dino-base + sam-vit-base  | **Person WITHOUT hard hat** (conf 0.61, 216/216 frames agree) | **Person WITH hard hat** (conf 0.61, 107/125 frames agree) |
| grounding-dino-tiny + sam-vit-large | **Person WITHOUT hard hat** (conf 0.83, 176/215 frames agree) | **Person WITH hard hat** (conf 0.88, 108/128 frames agree) |
| grounding-dino-base + sam-vit-large | **Person WITHOUT hard hat** (conf 0.61, 216/216 frames agree) | **Person WITH hard hat** (conf 0.61, 107/125 frames agree) |

All 4 combos got both videos right. `dino-base` is more conservative
(lower, more uniform confidence, ~0.61) but 100% frame-agreement on the
no-hard-hat clip; `dino-tiny` is more confident (~0.83–0.88) but slightly
less unanimous frame-to-frame. As expected, the SAM variant never changes
the answer — only the DINO row does.

## 2. Hardware adequacy (RTX 3080, 10GB VRAM, 9.86GB free at test start)

| Model combo | Peak VRAM | Headroom | Avg speed (every-frame) |
|---|---|---|---|
| grounding-dino-tiny + sam-vit-base  | 2.58 GB | 7.3 GB free | 3.6 fps |
| grounding-dino-base + sam-vit-base  | 2.80 GB | 7.1 GB free | 3.2 fps |
| grounding-dino-tiny + sam-vit-large | 3.91 GB | 6.0 GB free | 2.4 fps |
| grounding-dino-base + sam-vit-large | 4.14 GB | 5.9 GB free | 2.3 fps |

**All 4 combos are VRAM-adequate for this hardware** — even the heaviest
(dino-base + sam-vit-large) peaks at ~4.1GB, well under half the 3080's
10GB. Extrapolating from the measured base→large SAM delta (~1.3GB), the
untested `sam-vit-huge` (README: ~2.4GB vs large's ~1.2GB) would add
roughly another 1GB, landing combos around ~5–5.3GB peak — still
comfortably clear of the 10GB budget.

The binding constraint is **speed, not VRAM**: none of these hit real-time
(30fps) processing every frame (2.3–3.7 fps measured here). This matches
the README's guidance to use `--every-n-frames 3` for a demo — that
recovers effective throughput ~3x since detection is skipped and reused on
2 of every 3 frames — which is adequate for a demo but still not true
frame-by-frame real-time monitoring on this GPU. Model load times were not
a reliable signal in this run (varied 4–26s per combo) because
`HF_HUB_OFFLINE` was unset, so each load did a network freshness check
against the Hub rather than reading purely from the local cache.

**Recommendation:** `grounding-dino-tiny + sam-vit-base` (the scripts'
default) is the best fit for this hardware — lowest VRAM, fastest, and
tied for highest per-frame confidence in this test. Use `dino-base` if
the demo hits a scene where `dino-tiny` under- or mis-detects and the
~2x slower inference is acceptable; the extra ~0.2GB VRAM cost is
negligible on this GPU either way.
